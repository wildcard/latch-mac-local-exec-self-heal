# Incident 2026-10-02 — silent disconnect (S-NEW-D)

**When:** Friday 2 Oct 2026, about 22:08–22:27 PT (America/Vancouver).
**Where:** Operator Mac with kit `mac-local-exec-self-heal` **1.2.0** installed.
**Cloud view:** `ListMachines.connected=false` for that window.
**Classification:** **S-NEW-D**. Local process and heartbeat looked healthy. The LaunchAgent never relaunched. Cloud connect state is not visible on the Mac.

## What was on the Mac after the operator restarted Grok Bot (~22:28 PT)

- LaunchAgent `com.latch.grok-bot-local-exec-heal` was loaded.
- Long run count. Last exit code 0.
- No disable file.
- During the disconnect window the heal log was a continuous series of `ok reason=healthy` for the **pre-restart pid**, with `heartbeat_age` only about **31–45 seconds** (under the 180s stale threshold).
- Heal did not fire. That is 1.2.0 working as written, not a missed stale check.
- After a manual restart at about 22:28 PT: a **new pid**, `status=ok`, reason healthy.

The heartbeat timestamp was **moving** (age stayed in a healthy band). It was not a frozen `heartbeatAtMs`, and it was not a dead process.

## Why 1.2.0 could not help

1.2.0 treats “pid alive and heartbeat age < 180s and boot not explicitly unready” as success. It never asks whether the cloud still considers the machine connected. From the Mac, this outage was indistinguishable from a healthy idle.

## What 1.3.0 changes — and what it still will not do

In scope now:

- Do not call `healed` until readiness (process plus fresh heartbeat or `bootOutcome=ready`).
- Relaunch if `heartbeatAtMs` is actually frozen (`heartbeat_frozen`, default 120s). That would **not** have matched this incident.
- Honor `grok-bot-local-exec-heal.request` for a one-shot relaunch when a person, or a still-connected path, can write the file.
- After a long `ok` streak (`OK_HINT_SEC`, default 300s), write `escalateHint` naming S-NEW-D so a healthy `last.json` is not silent about the blind spot.

Still out of pure Mac heal:

- This incident. A moving sub-minute heartbeat plus a live pid will still log `ok`. The agent cannot see `ListMachines`.
- Recovery remains: the operator restarts Grok Bot, or someone who can still write on the Mac drops the request file.
- Sleep, lid, and network remain out of scope. This note does not claim those are solved.

A real S-NEW-D fix needs a signal the Mac watchdog does not have today (cloud connect state pushed onto disk, or a product reconnect inside Grok Bot).
