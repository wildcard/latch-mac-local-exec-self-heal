# Stage 0 safety and migration reconciliation

This follow-up supersedes the earlier proposal to enable helper healing by default.
The draft has one code writer. No installed/runtime files changed.

## Decisions and migration

- Script and plist defaults: `RECOVERY_MODE=observe`, `HEAL_ON_HELPER_MISSING=0`.
  Stage 0 blocks all app recovery, including Grok, Codex, local operator requests
  and beacon recovery. It does not poll/consume beacon requests or spend attempt budgets.
- Default reinstall deliberately resets old active/helper settings to Stage 0,
  even when a legacy plist had helper healing on. This is an intentional exception
  to environment preservation; beacon configuration, expectations, timings and
  remaining operator variables still survive. Invalid installer opt-ins fail
  before writing files.
- Only an invocation with `INSTALL_RECOVERY_MODE=active` enables active policy.
  Helper recovery additionally requires `INSTALL_HELPER_HEAL=1`. Explicit choices
  apply to the plist; RunAtLoad owns the single initial observation tick. The
  installer neither kickstarts the job nor invokes a second script tick. A later
  default reinstall returns to Stage 0 and disables all automatic healing. The
  owner must explicitly approve the intended installation policy. None of these
  operations was performed live.
- There is no authoritative all-lanes-idle signal. A PID-bound one-use idle lease
  is local authorization only. It does not prove cloud jobs, chats or other work
  are idle. It covers helper loss only. Owners must park/checkpoint/verify all
  affected work before a separately approved active recovery operation.

## Signal and continuity boundaries

- Missing, unreadable, invalid or permission-denied process identity is unknown,
  not an absent app. A confirmed absent PID can still be a process-down signal
  under explicitly active policy. Helper scans require nonempty valid process
  output including the main process; unknown scans cannot become zero helpers.
- Heartbeat samples must be finite, not future-dated, and PID-matched. Missing or
  mismatched samples cannot authorize a stale-heartbeat recovery.
- Frozen timestamps and weak socket hints are observe-only. A valid independent
  stale-heartbeat or other strong signal can still be evaluated in active mode;
  a weak hint itself cannot authorize a restart.
- All shell restart paths require a valid continuity sample. First active tick,
  inactive prior sample, unknown/unsafe clock state, backwards clocks, a gap over
  180s or wall/monotonic divergence over 2s blocks recovery without an attempt.
  A private, owned, atomic 0600 clock contains only wall/monotonic timestamps and mode.
- This is a conservative wake-like-gap heuristic, not authoritative wake detection.
  Short sleeps or platform-specific uptime behavior may escape it. No real wake
  test was performed. Stage 0 blocks restarts regardless. Unattended active rollout
  must not be justified by these simulations or by an assumption that wake handling
  is complete.
- Codex crash-only remains crash-only; it cannot detect a live silent disconnect.
  Grok helper loss remains a proxy, `cloudConnectObservable=false`, and genuine
  Prove D remains open. A process kill or synthetic stale data is not Prove D.

## Subsequent independent verification of reported concerns

External review raised the following concerns; they were verified locally before
being treated as defects. No private crash reports or unrelated session data were
read for these reproductions.

- Apple Python 3.9.6 rejected the four-digit fractional macOS timestamp format
  after offset normalization. The parser now normalizes one through nine digits
  to six (truncating nanoseconds), using synthetic two-object IPS and legacy text
  fixtures. Invalid, undated and future events still fail closed.
- The installer's so-called dry-run was a real second script invocation. Combined
  with startup, it could advance observation continuity immediately. The redundant
  direct invocation and kickstart were removed. A full temporary-HOME installer
  test uses fake launchctl/app commands and verifies no script tick is executed.
- Codex joined separate process/argv snapshots. It now uses one macOS `comm`
  snapshot without collecting argv; unsupported identity formats fail closed.
  This removes that join race, not every possible process change after observation.
- Grok's quit-timeout fallback used broad `pkill -f`. It was removed. An incomplete
  gentle quit now records `heal_incomplete`, `readiness=quit_timeout`,
  `action=quit_attempt`, retains the spent attempt, and stops without force-killing
  or issuing a duplicate open. Only stubs exercise this path in tests.
- The helper hint incorrectly implied any request would relaunch. It now states
  that requests are candidates only under explicit active mode and all guards.
- A current-owner 0600 legacy `{attempts:[timestamps]}` ledger remains compatible:
  the Grok budget is preserved, cap/backoff blocks without rewriting, and an
  allowed attempt upgrades it to keyed form. Unsafe ownership/mode or malformed
  data still blocks. No installed ledger was rewritten.
- Status exposes `recoveryMode`, `observationStatus` and `restartGuardResult` as
  allowlisted values. A healthy tick no longer hides an unevaluated/blocked clock;
  requested recovery still reports ledger/clock refusal in readiness. Codex keeps
  its own nested refusal status. Health and permission to recover are separate.

Current docs and PR prose omit unnecessary local paths, account IDs, runtime PIDs,
custom installed labels, exact observation timestamps and remote-agent identifiers.
The diff was reviewed for both identifying metadata and secrets; token scanning is
only supplementary. Removed metadata remains reachable in earlier commits and may
remain in prior PR revisions or caches. No history rewrite or visibility change was
performed, so no claim of complete erasure is made.

The final safe suites for this follow-up passed 117 shell cases, 47 Python tests
and 15 Worker tests. Apple Python 3.9.6 and Bash 3.2.57 were used. A read-only
single-snapshot platform check recognized the running main executable and
collected no argv; only booleans were retained in its output. No live recovery
was attempted. No external privacy-review clearance is claimed for this head.
