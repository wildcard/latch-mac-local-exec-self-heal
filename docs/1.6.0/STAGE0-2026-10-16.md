## Decisions and migration

- Script and plist defaults: `RECOVERY_MODE=observe`, `HEAL_ON_HELPER_MISSING=0`.
  Stage 0 blocks all app recovery, including Grok, Codex, local operator requests
  and beacon recovery. It does not poll/consume beacon requests or spend attempt budgets.
- Default reinstall deliberately resets old active/helper settings to Stage 0,
  even when a legacy plist had helper healing on. This is an intentional exception
  to environment preservation; beacon configuration, expectations, timings and
  remaining operator variables still survive. Invalid installer opt-ins fail
  before writing files.
- Only an invocation with `INSTALL_RECOVERY_MODE=active` enables active policy.
  Helper recovery additionally requires `INSTALL_HELPER_HEAL=1`. Explicit choices
  apply to both the plist and immediate post-install tick. A later default
  reinstall returns to Stage 0. None of these operations was performed live.
- There is no authoritative all-lanes-idle signal. A PID-bound one-use idle lease
  is local authorization only. It does not prove cloud jobs, chats or other work
  are idle. It covers helper loss only. Owners must park/checkpoint/verify all
  affected work before a separately approved active recovery operation.

## Signal and continuity boundaries

- Missing, unreadable, invalid or permission-denied process identity is unknown,
  not an absent app. A confirmed absent PID can still be a process-down signal
  under explicitly active policy. Helper scans require nonempty valid process
  output including the main process; unknown scans cannot become zero helpers.
- Heartbeat samples must be finite, not future-dated, and PID-matched. Missing or
  mismatched samples cannot authorize a stale-heartbeat recovery.
- Frozen timestamps and weak socket hints are observe-only. A valid independent
  stale-heartbeat or other strong signal can still be evaluated in active mode;
  a weak hint itself cannot authorize a restart.
- All shell restart paths require a valid continuity sample. First active tick,
  inactive prior sample, unknown/unsafe clock state, backwards clocks, a gap over
  180s or wall/monotonic divergence over 2s blocks recovery without an attempt.
  A private, owned, atomic 0600 clock contains only wall/monotonic timestamps and mode.
- This is a conservative wake-like-gap heuristic, not authoritative wake detection.
  Short sleeps or platform-specific uptime behavior may escape it. No real wake
  test was performed. Stage 0 blocks restarts regardless. Unattended active rollout
  must not be justified by these simulations or by an assumption that wake handling
  is complete.
- Codex crash-only remains crash-only; it cannot detect a live silent disconnect.
  Grok helper loss remains a proxy, `cloudConnectObservable=false`, and genuine
  Prove D remains open. A process kill or synthetic stale data is not Prove D.
