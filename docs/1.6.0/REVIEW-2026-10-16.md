## Approval and review gates

Default reinstall disables all automatic healing. Installation itself requires an
explicit owner installation policy: accept Stage 0 observation or separately approve
an active maintenance policy. Checkpoint and park all affected work, verify idleness
with its owners, preserve rollback material, and use an independent observer before
any approved disruptive proof. A heartbeat, helper count or idle lease is insufficient.

A bounded process-down or crash proof requires a specified target, one permitted
attempt, a time limit and stop conditions. It proves S1 only. Prove D requires a
genuine cloud disconnect, specifically approved recovery, reconnection and successful
real remote execution from the original path. Synthetic stale data or a request made
while healthy cannot substitute. Installation, live proof and merge remain separate gates.

The separate read-only Cursor CLI review could not authenticate. No independent
Cursor findings or clearance were produced. No existing remote agent was resumed.
