## Defects fixed

1. macOS `ps comm` returns the full executable path. The Codex matcher accepted
   only the short `ChatGPT` name, preventing observation of the actual main process.
   Both forms now require the exact bundle executable; helper/Classic decoys remain excluded.
2. The shell's default `STATE` was not passed as `HEAL_STATE` to the watcher.
   Normal LaunchAgent invocation therefore lost the prior launch required by
   `crash_only`. A temporary-HOME integration test exercises this exact invocation.
3. Failed process scans returned an empty list, allowing `any_exit` or a prior
   crash to authorize a reopen without evidence that the process was absent.
   Scan failure now returns `process_scan_error`, action none; probe failure is incomplete.
4. Crash matching used arbitrary text tokens and file mtime. A copied/touched old
   report or a different primary bundle mentioning Codex could pass. Primary
   identity plus explicit event time after a valid prior observation are now required.
   Missing/future event time fails closed. Both two-part JSON IPS and legacy text
   crash reports are tested, including Python 3.9 timezone spelling and a report
   exceeding the old 64 KiB limit (new bound 4 MiB).
5. An existing ledger missing `attempts`, or containing JSON null, could be treated
   as a fresh budget. It now fails closed without rewriting the evidence.
6. The new operator writer command followed HTTP redirects, potentially carrying
   its Authorization header beyond the configured endpoint. All redirects are
   refused; tests use mocked requests only.

## Minimal staged live approval

Installation, live proof and merge are separate gates. Ask for the exact tested
head to be installed in an agreed maintenance window, with an explicit helper
policy decision (`HELPER_IDLE_REQUIRED=1` if retaining the PID-bound helper idle
lease, or explicit acceptance of policy (a)). Preserve existing beacon settings;
do not configure new credentials. The installer itself can trigger recovery.

Before installation or any disruptive test, checkpoint and push each affected
workstream, record all Grok/Codex/worker activity, coordinate owners to park it,
and verify actual idleness through the owning systems. A heartbeat and helper
count cannot establish cloud-job idleness. Maintain a hold while preparing;
preserve current scripts/plist/state and record an exact rollback procedure.
Use a separate approved observer independent of the app being tested.

A bounded S1 process-down or Codex crash proof requires explicit permission for
one specified fault/target, one recovery attempt, a hard time limit and stop
conditions. Keep all other work held, collect before/after PIDs and real readiness,
and stop rather than retry beyond the approved attempt. A deliberate ordinary
Codex quit should stay down under crash_only. Never enable any_exit as a shortcut.

S1 success does not close Prove D. Prove D requires a genuine cloud disconnect,
recorded cloud-disconnected state, one specifically approved helper/beacon
recovery, cloud reconnection and a successful real remote command from the
original agent path. Fake/stale heartbeat fixtures and a synthetic request made
while the link is healthy cannot substitute. Prefer a real qualifying event;
do not manufacture one by changing network/security settings. If no such event
occurs, leave Prove D open. Merge remains separately unapproved.
