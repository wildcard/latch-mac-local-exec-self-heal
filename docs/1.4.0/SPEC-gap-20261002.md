## 2. What is not working as expected

### 2.1 Expectation gap (product)

**Claimed (operator-facing):** local-exec drops self-heal within ~60s so night shift / Mac-dependent bots can resume without babysitting.

**Actual (current kit):** watchdog only detects **dead main process**, **stale dune-reliability heartbeat (>180s)**, or **non-ready `bootOutcome`**, then quit+`open -ga "Grok Bot"`. Success is defined as **process PID exists within ~30s** — **not** as `ListMachines.connected=true` or a ready local-exec session.

So tonight’s failure mode — **link stays down after the heal wait** — is either:

- **Out of documented scope** (sleep/lid/network) but **under-sold as a hard limit** in the publish story, or  
- **In scope but incomplete**: process/heartbeat heal without **post-relaunch local-exec readiness**, and no **observable “cannot heal — escalate”** path for bots.

### 2.2 Technical gaps (kit 1.2.0)

| ID | Gap | Why it hurts |
|---|---|---|
| G1 | Heal success = process up only | App can be “healed” while fleet still sees `connected=false` |
| G2 | No post-relaunch wait for `bootOutcome=ready` / fresh heartbeat | Premature `healed` in `last.json` |
| G3 | No Mac-side classification of **unhealable** causes | Agents wait 60s then strand; no structured escalate reason |
| G4 | No automated scenario tests in the kit | Publish claimed self-heal without a prove matrix |
| G5 | Diagnostics unreachable when link is down | Correct by design for remote Shell; need **on-Mac last.json richness** + optional user-visible cue so morning triage is possible |
| G6 | Publish copy may over-promise “local-exec self-heal” vs “desktop process relaunch” | Public pack / template v3 in queue — needs version bump + honest matrix |

### 2.3 Tonight’s new scenario (name it)

**S-NEW — “Zombie / silent disconnect”:**  
`ListMachines.connected=false` persists across ≥1 LaunchAgent tick window (~60s+) while we cannot prove process state. Subcases after reconnect diagnostics:

- **S-NEW-A:** process down, heal did not run (disabled / unloaded / Mac asleep)  
- **S-NEW-B:** process down, heal ran, relaunch failed (`heal_failed`)  
- **S-NEW-C:** process up (or relaunched), heartbeat/boot never becomes ready → local-exec never reconnects  
- **S-NEW-D:** process + heartbeat look healthy on Mac, but cloud still shows disconnected (path/account — **out of LaunchAgent reach**)

S-NEW-C is the primary **in-scope fix** candidate. S-NEW-D and sleep/lid/network stay **out of heal loop** but must be **classified and escalated**, not silently waited.

| S10 | Intentional quit | Yes (by design) | Relaunches unless `.disable` — documented risk | Live optional |

## 4. Definition of Done (what solves the current issue)

**Product DoD — kit ≥1.3.0 (proposed), template bump (v3 → v4 or patched story):**

1. **Honest contract** in README + skill + CHANGELOG + publish copy:  
   - Self-heal restores **Grok Bot desktop + local-exec readiness signals on the Mac**.  
   - It does **not** wake a sleeping Mac, open a lid, or repair WAN/VPN/sign-in.  
   - Fleet promise: after a **healable** drop, agents soft-park ≤60–90s, then either resume on `connected=true` **or** get a clear escalate reason from `last.json` / skill — never silent strand.

2. **Heal completeness (G1/G2/S7):** after relaunch, wait/poll for readiness (process + heartbeat and/or `bootOutcome=ready`) within a bounded window; write `healed` only then; otherwise `heal_incomplete` / `heal_failed` with reason.

3. **Classification (G3/S-NEW):** `last.json` always updated each tick with enough fields for triage (`status`, `reason`, `action`, `pid`, `heartbeatAgeSec`, `lastHeal*`, and new `readiness` / `escalateHint` when stuck).

4. **Test pack (G4):** kit ships a `tests/` (or `prove/`) harness runnable on a connected Mac that covers S1–S7 at minimum (fixtures where kill is unsafe); exit non-zero on fail; receipt written under `/workspace` or Mac Logs.

5. **Live prove on `DEMO-MAC`:**  
   - S1 kill-and-recover with `ListMachines` flipping false→true (or documented equivalent readiness).  
   - S4 healthy.  
   - S5 disable.  
   - One intentional S-NEW observation: if connected stays false while Mac awake, `last.json` must not claim healthy-without-caveat.

6. **Fleet skill update:** `grok-bot-mac-local-exec-self-heal` documents the matrix, readiness wait, and escalate path; Latch + Grok Bot verify install after reconnect.

7. **Publish update:** bump VERSION + CHANGELOG; refresh the Latch public pack and publish notes so the queued “v2/v3 self-heal” story is corrected (not left claiming a capability the prove matrix failed). **Do not merge/publish until operator GO** (overnight operating practice).

**Not DoD:** inventing a second remote watchdog from the box; claiming sleep/network heal; driving unrelated app UI; merging unrelated product PRs without the operator.
